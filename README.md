# Goalspec

Goalspec is a project-local Goal-Driven Prompt framework for AI-assisted development.

It is not a task scheduler. The public model is:

- `Goal`: the final user goal.
- `Criteria`: the required success standards used to judge whether the goal is reached.
- `Constraints`: boundaries the AI must not violate while executing.

Implementation starts only from the frozen Goal-Driven Prompt generated by Goalspec.

## Install

```bash
export PATH="/path/to/goalspec-repo:$PATH"
cd /path/to/project
git init
goalspec init
```

Install AI adapter instructions when needed:

```bash
goalspec install-ai codex   # or claude / lingma
```

## User Commands

The ordinary user command surface is intentionally small:

```text
/goalspec start <intent>
/goalspec source <path>
/goalspec end
/goalspec run
/goalspec status
/goalspec reopen <reason>
```

`/goalspec run` is the only user command that begins implementation.

Natural-language confirmation is supported:

```text
确认
修改为...
不同意，第 C2 条改成...
```

Confirmation freezes the reviewed Goal, Criteria, and Constraints. It does not begin implementation.

## Lifecycle

1. `/goalspec start <intent>` opens a formal intake window.
2. `/goalspec source <path>` adds source material to the open intake window.
3. `/goalspec end` closes the intake window. Before this, Goalspec must not freeze artifacts, generate a Goal-Driven Prompt, or modify business code.
4. The AI drafts Goal, Criteria, Constraints, out-of-scope, and blocking questions for human review.
5. Human confirmation freezes the Goal, Criteria, and Constraints and generates `.goalspec/active/goal-driven-prompt.md`.
6. Goalspec stops and waits.
7. `/goalspec run` verifies frozen artifacts and the prompt hash, then outputs the Goal-Driven Prompt execution envelope.

If a prompt is missing, stale, or not backed by frozen artifacts, `/goalspec run` refuses execution with `GOALSPEC_RUN_ALLOWED: false`.

## Criteria

Criteria are required by default. Do not add repetitive `required: true` fields.

Use `optional_criteria` for useful ideas that must not block completion.

Each criterion must be:

- Clear.
- Decidable from evidence.
- Relevant to the Goal.
- Minimal, without implementation steps or technology choices.

Avoid vague wording such as "reasonable", "good", "optimized", "correct", "complete", "完整", "正确", or "优化" unless the wording is concretely defined.

## Execution

The generated prompt defines exactly one Master Agent and one Subagent. If an AI tool does not support explicit subagents, the adapter must visibly simulate:

```text
Master Evaluation
Subagent Work
Evidence/Progress Report
Master Evaluation
```

The Subagent works toward the frozen Goal under the frozen Constraints. The Master Agent evaluates progress strictly against the frozen Criteria.

Internal attempts or execution scopes may be used for traceability and safety, but internal task records are not success standards.

## Evidence And Verdict

Evidence records facts, commands, results, artifacts, and Criteria references. Evidence may also record an internal attempt.

The Subagent may produce evidence. The Subagent cannot produce the final success verdict.

Only the Master Agent or Guardian can judge whether evidence satisfies Criteria.

Completion succeeds only when all required Criteria have pass verdicts, Constraints are not violated, and the completion gate passes.

## Status

`/goalspec status` reports:

```text
STATE
GOAL
FROZEN
PROMPT_READY
RUN_ALLOWED
NEEDS_HUMAN_CONFIRMATION
BLOCKERS
UNMET_CRITERIA
NEXT_USER_ACTION
```

Status does not expose internal task records as the user-facing goal.
